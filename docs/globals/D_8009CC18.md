# D_8009CC18 — GPU status pointer (GP1 read side)

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009CC18` |
| C name | `gGpuGp1StatusPtr` |
| slot address | `0x8009CC18` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F801814` |
| points at | GPU GP1 port / GPUSTAT register |
| assembler label | `GPU_GP1_STATUS_ASM` in `include/game/gpu_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009CC18
    /* 8D418 8009CC18 1418801F */ .word 0x1F801814
```

File offset `0x8D418` of `SLUS_007.39` holds `14 18 80 1F`, i.e. `0x1F801814` —
the same address as `gGpuGp1PortPtr`, but a different retail variable.

## Hardware meaning

`0x1F801814` reads as GPUSTAT. This unit stores the value, waits when bit
`0x400000` is set, and then spins until bit 31 toggles — a frame-synchronisation
wait on the GPU status, not a command write. The name says "status" to separate
the read-only use from the command-port use of the other pointer.

## Correct C type

`volatile u32 *` — the status word changes on its own and is read in a loop.

## Users

* `func_80091270` — timing helper: saves the status, waits for the GPU, and
  measures elapsed ticks with the timer counter.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
u32 status = *gGpuGp1StatusPtr;          /* reads GPUSTAT       */
while (!(*gGpuGp1StatusPtr & 0x80000000)) { }  /* waits for bit 31 */
u32 addr = (u32)gGpuGp1StatusPtr;        /* 0x1F801814          */
```

## C integration status

Renamed from `D_8009CC18` to `gGpuGp1StatusPtr` in its single user; the retail
symbol is kept with `__asm__("D_8009CC18")`. No object is defined, the retail
word stays in `asm/us/main.s`, and the unit still compiles to the exact retail
bytes (SHA-256 compared before and after the rename).
