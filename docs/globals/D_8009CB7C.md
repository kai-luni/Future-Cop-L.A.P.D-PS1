# D_8009CB7C — common memory access delay pointer

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009CB7C` |
| C name | `gComAccessDelayPtr` |
| slot address | `0x8009CB7C` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F801020` |
| points at | common delay register (bus timing for all devices) |
| assembler label | `COM_ACCESS_DELAY_ASM` in `include/game/cdrom_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009CB7C
    /* 8D37C 8009CB7C 2010801F */ .word 0x1F801020
```

File offset `0x8D37C` of `SLUS_007.39` holds `20 10 80 1F`, i.e. `0x1F801020`.

Write in `func_8008F6D8`:

```
    /* 7FF98 8008F798 0A80033C */  lui        $v1, %hi(D_8009CB7C)
    /* 7FF9C 8008F79C 7CCB638C */  lw         $v1, %lo(D_8009CB7C)($v1)
```

## Hardware meaning

`0x1F801020` is the common delay register: it sets the base access timing that
applies to all memory-mapped devices. Both users write the same value `0x1325`
during CD-ROM initialisation, before the first command is issued. The register
number follows public PlayStation documentation; the code shows the constant,
not its field breakdown.

## Correct C type

`u32 *` in both users.

## Users

* `func_8008F6D8` — reset path, writes `0x1325` after clearing the CD ports.
* `func_8008F8E8` — `CD_init`: writes `0x1325`, then issues CdlNop, CdlReset,
  CdlDemute and CdlSync.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gComAccessDelayPtr = 0x1325;         /* sets the common timing */
u32 addr = (u32)gComAccessDelayPtr;   /* 0x1F801020, no effect  */
```

## C integration status

Renamed from `D_8009CB7C` to `gComAccessDelayPtr` in its two C users (the other
two units mention it only in comments); the retail symbol is kept with
`__asm__("D_8009CB7C")`. No object is defined, the retail word stays in
`asm/us/main.s`, and the affected units still compile to the exact retail bytes
(SHA-256 compared before and after the rename).
