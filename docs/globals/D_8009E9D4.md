## Hardware meaning

`0x1F801098` is `DMA1_CHCR`, the channel control register of DMA channel 1,
the MDEC input channel:

* bit 24 — start/busy (reads 1 while the transfer runs)
* bits 28–30 — sync mode
* bit 0 — transfer direction

The MDEC path stops the channel with `*ptr = 0` and starts a transfer with
`0x01000200`, then spins on bit 24 with a 0x100000 iteration timeout. The
neighbouring `D_8009E9C8` (DMA0, MDEC output) and `D_8009E9F4` (MDEC control)
are separate globals. Bit numbering follows public PlayStation documentation.

| unit | declaration |

## Users

* `func_80096150` — clears the channel twice while resetting MDEC.
* `func_800962D0` — sets the control bits around a transfer, writes
  `0x01000200` to start it.
* `func_800963F0` — waits for bit 24 to clear, with timeout.
* `func_8009649C` — clears the channel on the timeout path.

`analysis/refs.json` lists 9 references to the slot in 4 functions, all 4-byte
loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDma1ChannelCtrlPtr = 0x01000200;           /* starts MDEC input DMA */
if (*gDma1ChannelCtrlPtr & 0x01000000) { }   /* polls the busy bit    */
u32 addr = (u32)gDma1ChannelCtrlPtr;         /* 0x1F801098, no effect */
```

## C integration status

Renamed from `D_8009E9D4` to `gDma1ChannelCtrlPtr` in the four C users that
declare it; the retail symbol is kept with `__asm__("D_8009E9D4")`. No object is
defined, the retail word stays in `asm/us/main.s`, and all five units that
mention the symbol still compile to the exact retail bytes (SHA-256 compared
before and after the rename).
