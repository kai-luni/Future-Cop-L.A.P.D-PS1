## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009E9C8
    /* 8F1C8 8009E9C8 8810801F */ .word 0x1F801088
```

File offset `0x8F1C8` of `SLUS_007.39` holds `88 10 80 1F`, i.e. `0x1F801088`.
The following slots of the same block are `D_8009E9CC`
(`0x1F80108C`, block control) and `D_8009E9D4` (`0x1F801098`, channel 1
control) — separate globals, not renamed here.

## Hardware meaning

`0x1F801088` is `DMA0_CHCR`, the channel control register of DMA channel 0, the
MDEC output channel:

* bit 24 — start/busy
* bits 28–30 — sync mode
* bit 0 — transfer direction

The MDEC code stops the channel with `*ptr = 0` and starts an output transfer
with `0x01000201`. Bit numbering follows public PlayStation documentation.

## Users

* `func_80096150` — clears the channel while resetting the MDEC path.
* `func_80096240` — writes `0x01000201` to start the output transfer.
* `func_8009649C` — clears the channel on the timeout path.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDma0ChannelCtrlPtr = 0x01000201;   /* starts MDEC output DMA */
*gDma0ChannelCtrlPtr = 0;            /* stops the channel      */
u32 addr = (u32)gDma0ChannelCtrlPtr; /* 0x1F801088, no effect  */
```

## C integration status

Renamed from `D_8009E9C8` to `gDma0ChannelCtrlPtr` in its three C users; the
retail symbol is kept with `__asm__("D_8009E9C8")`. No object is defined, the
retail word stays in `asm/us/main.s`, and all three units still compile to the
exact retail bytes (SHA-256 compared before and after the rename).
