# D_8009DED0 — DMA channel 2 block control pointer

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009DED0` |
| C name | `gDma2BlockCtrlPtr` |
| slot address | `0x8009DED0` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F8010A4` |
| points at | DMA channel 2 block control register (BCR2) |
| assembler label | `DMA2_BLOCK_CTRL_ASM` in `include/game/dma_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
nonmatching D_8009DED0

dlabel D_8009DED0
    /* 8E6D0 8009DED0 A410801F */ .word 0x1F8010A4
```

The bytes at file offset `0x8E6D0` (`0x800 + 0x8009DED0 - 0x80010000`) are
`A4 10 80 1F`, i.e. `0x1F8010A4`. The slot sits in the same pointer block as
`D_8009DECC` (`0x1F8010A0`) and `D_8009DED4` (`0x1F8010A8`), the address and
control registers of the same DMA channel.

A write through the pointer, `func_800946A8` at `0x80094660`:

```
    /* 84E60 80094660 0A80033C */  lui        $v1, %hi(D_8009DED0)
    /* 84E64 80094664 D0DE638C */  lw         $v1, %lo(D_8009DED0)($v1)
    /* 84E68 80094668 10004234 */  ori        $v0, $v0, 0x10
    /* 84E6C 8009466C 000062AC */  sw         $v0, 0x0($v1)
```

The first two instructions load the pointer, the last stores the block control
word into the register.

## Hardware meaning

`0x1F8010A4` is `DMA2_BCR` (block control) of DMA channel 2, the GPU channel:

* bits 0–15 — block size in words (0 means 0x10000 words)
* bits 16–31 — number of blocks

The game writes `(blocks << 16) | 0x10`, i.e. `blocks` blocks of 16 words each,
directly before starting the transfer in the channel control register. The
channel and register numbering follows public PlayStation documentation; the
game's own code only shows the address and the shifted values.

## Correct C type

`volatile u32 *` — pointer to a volatile 32-bit register. The pointer variable
itself can be read more than once, but the pointee is a hardware register.

Units keep the types they were matched with, because the qualification is
visible in the object code:

| unit | declaration |
| --- | --- |
| `func_8009446C`, `func_800946A8` | `volatile u32 *` |
| `func_800949A0` | `u32 *` |

## Users

* `func_8009446C` — sets `(blocks << 16) | 0x10` before starting a GPU upload
  (`CHCR2 = 0x1000201`).
* `func_800946A8` — sets the same value before starting a GPU read-back
  (`CHCR2 = 0x1000200`).
* `func_800949A0` — writes `0`, clearing block size and count before a packet
  based transfer.

`analysis/refs.json` lists 3 references to the slot, all 4-byte loads; the slot
itself is never written.

## Accessing the variable vs. the register

```c
*gDma2BlockCtrlPtr = (blocks << 16) | 0x10;  /* writes DMA2_BCR   */
u32 addr = (u32)gDma2BlockCtrlPtr;           /* 0x1F8010A4, no side effect */
```

## C integration status

Renamed from `D_8009DED0` to `gDma2BlockCtrlPtr` in the three C users; the
retail symbol is kept with `__asm__("D_8009DED0")`. No object is defined, the
retail word stays in `asm/us/main.s`, and all three units still compile to the
exact retail bytes (SHA-256 compared before and after the rename).
