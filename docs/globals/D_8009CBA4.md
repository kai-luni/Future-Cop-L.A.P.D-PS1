## Retail evidence

```
dlabel D_8009CBA4
    /* 8D3A4 8009CBA4 F010801F */ .word 0x1F8010F0
```

File offset `0x8D3A4` of `SLUS_007.39` holds `F0 10 80 1F`, i.e. `0x1F8010F0`.

## Hardware meaning

`0x1F8010F0` is `DPCR` (four bits per DMA channel: priority and enable). This
pointer belongs to the CD-ROM sector path, which enables the CD channel with
`|= 0x8000` — bits 12–15, the nibble of DMA channel 3. Five retail pointers hold
this same address; each is named by the path that uses it, and the doc does not
claim more than the bits the code sets.

## Correct C type

`volatile u32 *`.

## Users

* `func_8008FC30` — sets the CD channel enable bit before the transfer.
* `func_8008FD30` — same enable in the variant path.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDmaControlCdromPtr |= 0x8000;      /* enables the CD channel */
u32 addr = (u32)gDmaControlCdromPtr; /* 0x1F8010F0             */
```
