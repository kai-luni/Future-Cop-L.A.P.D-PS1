## Retail evidence

    /* 8E6D4 8009DED4 A810801F */ .word 0x1F8010A8
```

File offset `0x8E6D4` of `SLUS_007.39` holds `A8 10 80 1F`, i.e. `0x1F8010A8`.
The slot is the third word of the DMA2 group (`0x1F8010A0` address,
`0x1F8010A4` block control, `0x1F8010A8` channel control).

    /* 84E74 80094674 D4DE428C */  lw         $v0, %lo(D_8009DED4)($v0)
    /* 84E78 80094678 01028434 */  ori        $a0, $a0, (0x1000201 & 0xFFFF)
```

## Hardware meaning

`0x1F8010A8` is `DMA2_CHCR`, the channel control register of DMA channel 2,
the GPU channel:

* bit 24 — start/busy (write 1 to start, reads 1 while the transfer runs)
* bits 28–30 — sync mode (2 = linked list, 1 = block)
* bits 16–23 — step and chunk size for block mode
* bit 0 — transfer direction (0 = to RAM, 1 = from RAM)

Values written by the game: `0x1000201` (start, from RAM), `0x1000200`
(start, to RAM), `0x01000401` and `0x401` (programming, not started), and the
channel is polled with `& 0x1000000`. Bit numbering follows public PlayStation
documentation.

## Correct C type

`volatile u32 *` — pointer to a volatile 32-bit register.

| unit | declaration |
| --- | --- |
| `func_8009446C`, `func_800946A8`, `func_80094A3C`, `func_8009509C`, `func_8009520C`, `func_800953F0`, `func_800954DC`, `func_800955C8`, `func_8009570C` | `volatile u32 *` |
| `func_800949A0`, `func_80094F4C` | `u32 *` |

`func_80094CEC` reaches the register only through inline assembly
(`lui $2, %hi(D_8009DED4)` / `lw $2, %lo(D_8009DED4)($2)`), so the file keeps
the retail name and stays unchanged.

## Users

* `func_8009446C` — starts a GPU upload (`0x1000201`).
* `func_800946A8` — starts a GPU read-back (`0x1000200`).
* `func_800949A0` — programs `0x01000401` for a packet transfer.
* `func_80094A3C` — polls `& 0x1000000` before dispatching the next job.
* `func_80094F4C`, `func_8009520C` — program `0x401` in their reset paths.
* `func_8009509C`, `func_800953F0`, `func_800954DC`, `func_800955C8`,
  `func_8009570C` — wait for the channel to become idle.
* `func_80094CEC` — reads the register through inline assembly.

`analysis/refs.json` lists 22 references to the slot in 12 functions, all 4-byte
loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDma2ChannelCtrlPtr = 0x1000201;              /* starts the transfer  */
while (*gDma2ChannelCtrlPtr & 0x1000000) { }   /* waits for completion */
u32 addr = (u32)gDma2ChannelCtrlPtr;           /* 0x1F8010A8, no effect */
```

## C integration status

Renamed from `D_8009DED4` to `gDma2ChannelCtrlPtr` in the eleven C users that
declare it; the retail symbol is kept with `__asm__("D_8009DED4")`. No object is
defined, the retail word stays in `asm/us/main.s`, and all twelve units that
mention the symbol still compile to the exact retail bytes (SHA-256 compared
before and after the rename).
