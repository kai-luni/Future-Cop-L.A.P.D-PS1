## Hardware meaning

`0x1F801C00` is the base of the SPU register file:

| offset | register |
| --- | --- |
| `0x000`–`0x17F` | 24 voices, 16 bytes each (volume, pitch, start address, ADSR, …) |
| `0x180` | main volume left, `0x182` right |
| `0x188` | reverb volume |
| `0x1A6` | transfer address |
| `0x1A8` | transfer FIFO |
| `0x1AA` | SPUCNT control |
| `0x1AC` | transfer control |
| `0x1AE` | SPUSTAT status |

The game reaches those registers through a struct over the block
(`Spu`, `SpuDebug`, `Unk9EEA4`, `Hardware`) or through a field such as
`field1A6`/`field1A8`/`field1AE` in `func_80097138`. Register layout follows
public PlayStation documentation.

## Users

14 functions reference the slot (`analysis/refs.json`: 75 references, all
4-byte loads; the slot itself is never written). The most substantial:

* `func_80096EB8` — driver entry: reads the block for voice and volume setup.
* `func_80097138` — SPU RAM transfer: programs the transfer address, writes the
  FIFO in chunks of up to 0x40 bytes and polls SPUSTAT.
* `func_800972F8` — clears and polls control bits `0x30`.
* `func_80098FE8`, `func_80099368`, `func_80099C58` — voice programming.
* `func_80021B90`, `func_80021BD0`, `func_80022F44`, `func_80096D58` — mention
  the symbol only in doc comments and stay unchanged.

## Accessing the variable vs. the register

```c
gSpuRegBasePtr->field1A6 = address;   /* writes the transfer address word   */
u32 base = (u32)gSpuRegBasePtr;       /* 0x1F801C00, no side effect         */
```

## C integration status

Renamed from `D_8009EEA4` to `gSpuRegBasePtr` in the fourteen C users that
declare it; the retail symbol is kept with `__asm__("D_8009EEA4")`. No object is
defined, the retail word stays in `asm/us/main.s`, and all eighteen units that
mention the symbol still compile to the exact retail bytes (SHA-256 compared
before and after the rename).
