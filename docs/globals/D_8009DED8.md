## Identity

## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009DED8
    /* 8E6D8 8009DED8 E010801F */ .word 0x1F8010E0
```

File offset `0x8E6D8` of `SLUS_007.39` holds `E0 10 80 1F`, i.e. `0x1F8010E0`.

## Hardware meaning

`0x1F8010E0` is `DMA6_MADR`, the memory address register of DMA channel 6, the
ordering-table clear channel. The unit stores the tail of the caller's table,
`arg0 + (count * 4 - 4)`, and lets the channel walk backwards.

## Correct C type

`u32 *`.

## Users

* `func_8009415C` — programs the OTC start address before starting the
  transfer.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDma6MemAddrPtr = (u32)(table + (count * 4 - 4));  /* programs MADR6 */
u32 addr = (u32)gDma6MemAddrPtr;                     /* 0x1F8010E0     */
```

## C integration status

Renamed from `D_8009DED8` to `gDma6MemAddrPtr` in its single user; the retail
symbol is kept with `__asm__("D_8009DED8")`. No object is defined, the retail
word stays in `asm/us/main.s`, and the unit still compiles to the exact retail
bytes (SHA-256 compared before and after the rename).
