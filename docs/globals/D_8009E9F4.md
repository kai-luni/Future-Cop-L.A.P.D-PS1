## Hardware meaning

`0x1F801824` is the MDEC control/status word:

* **write** `0x80000000` — reset the unit
* **write** `0x60000000` — enable data input and output
* **read** bit `0x20000000` — input FIFO full (the driver waits for it to clear)

The companion port `0x1F801820` (MDEC0) carries commands and parameters; the
game only touches the control/status word in these units. Bit meanings follow
public PlayStation documentation.

## Correct C type

`volatile u32 *` — pointer to a volatile 32-bit register. All units keep the
non-volatile types they were matched with, because the code only writes or
reads whole words and never benefits from a volatile pointee.

| unit | declaration |
| --- | --- |
| `func_80096150`, `func_8009635C` | `u32 *` |
| `func_80096484` | `int *` |
| `func_8009649C` | `volatile u32 *` |

`func_80096090` mentions the symbol only in a doc comment and stays unchanged.

## Users

* `func_80096150` — reset/enable sequence: writes `0x80000000`, then
  `0x60000000` twice around the DMA stop.
* `func_8009635C` — waits for the input FIFO bit `0x20000000` to clear, with a
  0x100000 iteration timeout.
* `func_80096484` — returns the current status word.
* `func_8009649C` — timeout path, reads the word again after clearing the DMA
  channel.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gMdecControlStatusPtr = 0x60000000;                 /* enables MDEC      */
if (*gMdecControlStatusPtr & 0x20000000) { }         /* input FIFO full   */
u32 addr = (u32)gMdecControlStatusPtr;               /* 0x1F801824        */
```

## C integration status

Renamed from `D_8009E9F4` to `gMdecControlStatusPtr` in its four C users; the
retail symbol is kept with `__asm__("D_8009E9F4")`. No object is defined, the
retail word stays in `asm/us/main.s`, and all five units that mention the
symbol still compile to the exact retail bytes (SHA-256 compared before and
after the rename).
