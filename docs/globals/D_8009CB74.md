# D_8009CB74 — CD-ROM parameter/interrupt-enable pointer

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009CB74` |
| C name | `gCdromParameterPtr` |
| slot address | `0x8009CB74` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F801802` |
| points at | CD-ROM parameter port (write) / interrupt enable (bank 1), bank dependent |

    /* 7F0AC 8008E8AC 74CB428C */  lw         $v0, %lo(D_8009CB74)($v0)

## Hardware meaning

`0x1F801802` is the second data port of the CD-ROM controller:

* **command bank** — parameter FIFO: command parameters are pushed here before
  the command byte
* **bank 1** — interrupt enable; the driver writes `7` to enable the three
  CD-ROM interrupt sources

Bank selection happens through `gCdromIndexStatusPtr` (`0x1F801800`). Register
behaviour follows public PlayStation documentation.

## Correct C type

`volatile u8 *` — byte-wide port.

| unit | declaration |
| --- | --- |
| `func_8008E7A0` | `volatile unsigned char *` |
| `func_8008F244`, `func_8008F6D8` | `volatile u8 *` |
| `func_8008F650`, `func_8008F7AC` | `u8 *` |

## Users

* `func_8008E7A0` — writes `7` (interrupt enable) in the setup path.
* `func_8008F244` — pushes the parameter bytes for a command.
* `func_8008F650`, `func_8008F6D8`, `func_8008F7AC` — further parameter and
  reset writes.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gCdromParameterPtr = value;         /* parameter byte / interrupt enable */
u32 addr = (u32)gCdromParameterPtr;  /* 0x1F801802, no side effect        */
```

## C integration status

Renamed from `D_8009CB74` to `gCdromParameterPtr` in its five C users; the
retail symbol is kept with `__asm__("D_8009CB74")`. No object is defined, the
retail word stays in `asm/us/main.s`, and the affected units still compile to
the exact retail bytes (SHA-256 compared before and after the rename).
