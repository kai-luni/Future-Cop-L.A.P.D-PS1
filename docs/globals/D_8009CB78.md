File offset `0x8D378` of `SLUS_007.39` holds `03 18 80 1F`, i.e. `0x1F801803`.
It is the fourth word of the CD-ROM port group (`0x1F801800`…`0x1F801803`).

## Hardware meaning

`0x1F801803` is the CD-ROM request register; its meaning depends on the bank
selected through `0x1F801800`:

* **bank 0** — request register (bit 7 busy, bits 0–2 acknowledge bits)
* **bank 1** — interrupt flag on read, interrupt acknowledge on write

The driver reads the flags with `& 7`, acknowledges by writing `7`, clears them
with `0`, and spins while `(*ptr & 7) != 0` during reset. Register layout
follows public PlayStation documentation.

## Users

7 functions reference the slot (`analysis/refs.json`: 17 references, all
4-byte loads; the slot itself is never written):

* `func_8008E7A0` — reads the stable flags, acknowledges and dispatches the
  interrupt mode.
* `func_8008F650` — forwards a byte and writes `0x20` (bank-dependent control).
* `func_8008F6D8` — reset: spins while flags are pending, writes `7` and `0`.
* `func_8008F7AC`, `func_8008F8E8` — command/response sequencing.
* `func_8008FC30`, `func_8008FD30` — sector read completion.

## Accessing the variable vs. the register

```c
if (*gCdromRequestStatusPtr & 7) { }      /* pending interrupt flags  */
*gCdromRequestStatusPtr = 7;              /* acknowledge              */
u32 addr = (u32)gCdromRequestStatusPtr;   /* 0x1F801803, no effect    */
```
