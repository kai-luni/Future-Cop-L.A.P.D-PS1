## Hardware meaning

`0x1F801814` is the GP1 port. Writes there are GP1 commands (display setup, DMA
direction, interrupt acknowledge, reset). Reads return GPUSTAT, the GPU status
word; the bits this game tests are documented below. Command numbering follows
the public PlayStation GP1 documentation.

Bits used by the code:

* `0x04000000` (bit 26) — tested before starting a transfer and inside the
  wait loops of `func_80094A3C`, `func_8009509C`, `func_800953F0`,
  `func_800954DC`, `func_800955C8`, `func_8009570C`.
* `0x08000000` (bit 27) — tested in the read-back path of `func_800946A8`.
* `0x7FF` and `0x3FFF` — copied into a packet field (`func_8009423C`) and into
  a GP0 command (`func_80095350`).

Values written through the pointer: `0`, `0x01000000`, `0x02000000`,
`0x04000000`, `0x04000002`, `0x04000003`, `0x09000001`, `0x10000007`, plus
arbitrary words in `func_80094928` and `func_800949E8`.

## Correct C type

`volatile u32 *` — pointer to a volatile 32-bit register, because GPUSTAT
changes asynchronously and each GP1 write has a side effect.

The units keep the types they were matched with:

| unit | declaration |
| --- | --- |
| `func_80094144` | `int *` |
| `func_8009423C`, `func_800949A0`, `func_800949E8`, `func_80094F4C`, `func_8009509C`, `func_80095350` | `u32 *` |
| `func_80094928`, `func_80094960` | `unsigned int *` |
| `func_8009446C`, `func_800946A8`, `func_80094A3C`, `func_8009520C`, `func_800953F0`, `func_800954DC`, `func_800955C8`, `func_8009570C` | `volatile u32 *` |

Unifying the qualification changed the object code of four units (shared
`volatile`) or seven units (shared non-volatile), so the historical types stay.

`analysis/refs.json` lists 34 references to the slot in 18 functions, all
4-byte loads, none of them a store — the slot is written once at startup and
never changed afterwards.

## Accessing the variable vs. the register

```c
u32 status = *gGpuGp1PortPtr;    /* GPUSTAT: hardware status, changes on its own */
*gGpuGp1PortPtr = 0x04000003;    /* GP1 command: side effect on the GPU          */
u32 addr = (u32)gGpuGp1PortPtr;  /* the slot value 0x1F801814, no side effect    */
```

The distinction matters when reading the C code: `if (*gGpuGp1PortPtr &
0x04000000)` polls the GPU, while `gGpuGp1PortPtr` alone is only the address.

## C integration status

Renamed from `D_8009DEC8` to `gGpuGp1PortPtr` in all C users; the assembler
symbol is bound with `__asm__("D_8009DEC8")`. `func_80094CEC` keeps the retail
name inside its hand-written assembly (`%hi(D_8009DEC8)` / `%lo(D_8009DEC8)`),
because GCC does not rewrite symbol names inside asm strings.
No object is defined, the retail
bytes remain in `asm/us/main.s` (`dlabel D_8009DEC8`), and all 18 affected units
still compile to the exact retail bytes (SHA-256 compared per unit, see
`docs/globals/README.md`).

Open point: turning the slot into a real C definition would need a data split at
`0x8009DEC8`, an absolute placement rule in the linker script, the removal of
the absolute `.set` alias for this symbol, and a byte comparison of the four
bytes — see `bericht-8009DEC8-c-globale-20261116.md` in the operations folder.
