# D_8009CB70 — CD-ROM command/response pointer

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009CB70` |
| C name | `gCdromCommandPtr` |
| slot address | `0x8009CB70` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F801801` |
| points at | CD-ROM command port (write) / response FIFO (read), bank dependent |
| assembler label | `CDROM_COMMAND_ASM` in `include/game/cdrom_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009CB70
    /* 8D370 8009CB70 0118801F */ .word 0x1F801801
```

File offset `0x8D370` of `SLUS_007.39` holds `01 18 80 1F`, i.e. `0x1F801801`.

Response read in `func_8008E7A0`:

```
    /* 7F03C 8008E83C 0A80023C */  lui        $v0, %hi(D_8009CB70)
    /* 7F040 8008E840 70CB428C */  lw         $v0, %lo(D_8009CB70)($v0)
```

## Hardware meaning

`0x1F801801` is the first data port of the CD-ROM controller. In the command
bank a write sends the command byte; in the response bank a read returns the
next byte of the response FIFO. The driver drains up to eight response bytes
into a buffer in the interrupt path, and pushes the command byte here in
`func_8008F244`. Bank selection happens through `gCdromIndexStatusPtr`
(`0x1F801800`). Register behaviour follows public PlayStation documentation.

## Correct C type

`volatile u8 *` — byte-wide port.

| unit | declaration |
| --- | --- |
| `func_8008E7A0` | `volatile unsigned char *` |
| `func_8008F244` | `volatile u8 *` |
| `func_8008F650`, `func_8008F7AC` | `u8 *` |

## Users

* `func_8008E7A0` — drains the response FIFO into `buf`.
* `func_8008F244` — sends the command byte after pushing the parameters.
* `func_8008F650` — forwards a caller-supplied byte.
* `func_8008F7AC` — command/response sequencing.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
command = *gCdromCommandPtr;      /* reads the next response byte   */
*gCdromCommandPtr = cmd;          /* sends a command byte           */
u32 addr = (u32)gCdromCommandPtr; /* 0x1F801801, no side effect     */
```

## C integration status

Renamed from `D_8009CB70` to `gCdromCommandPtr` in its four C users; the retail
symbol is kept with `__asm__("D_8009CB70")`. No object is defined, the retail
word stays in `asm/us/main.s`, and the affected units still compile to the exact
retail bytes (SHA-256 compared before and after the rename).
