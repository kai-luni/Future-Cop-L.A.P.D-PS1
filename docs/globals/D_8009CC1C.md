# D_8009CC1C — timer 1 counter pointer

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009CC1C` |
| C name | `gTimer1CounterPtr` |
| slot address | `0x8009CC1C` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F801110` |
| points at | root counter 1 value register |
| assembler label | `TIMER1_COUNTER_ASM` in `include/game/timer_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009CC1C
    /* 8D41C 8009CC1C 1011801F */ .word 0x1F801110
```

File offset `0x8D41C` of `SLUS_007.39` holds `10 11 80 1F`, i.e. `0x1F801110`,
which is the counter register of root counter 1 (timer 1). The following
register `0x1F801114` (mode) is `gTimer1ModePtr`.

## Hardware meaning

`0x1F801110` is the 16-bit counter of root counter 1. `func_80091270` reads it
twice until two consecutive reads agree, so the value is not captured while the
counter increments. The difference to a stored baseline (`D_8009CC20`) is the
elapsed time.

## Correct C type

`volatile u32 *` — the pointee must be volatile, otherwise the compiler could
fold the two reads into one and the stability check would be meaningless.

## Users

* `func_80091270` — samples the counter, waits for two equal reads and returns
  the elapsed ticks.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
do { now = *gTimer1CounterPtr; } while (now != *gTimer1CounterPtr);
u32 addr = (u32)gTimer1CounterPtr;   /* 0x1F801110, no effect */
```

## C integration status

Renamed from `D_8009CC1C` to `gTimer1CounterPtr` in its single user; the retail
symbol is kept with `__asm__("D_8009CC1C")`. No object is defined, the retail
word stays in `asm/us/main.s`, and the unit still compiles to the exact retail
bytes (SHA-256 compared before and after the rename).
