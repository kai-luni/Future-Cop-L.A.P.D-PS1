# D_8009DD14 — interrupt status pointer (halfword view)

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009DD14` |
| C name | `gInterruptStatusHalfPtr` |
| slot address | `0x8009DD14` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F801070` |
| points at | interrupt status register (I_STAT), used as a 16-bit view |
| assembler label | `INT_STATUS_HALF_ASM` in `include/game/intc_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009DD14
    /* 8E514 8009DD14 7010801F */ .word 0x1F801070
    /* 8E518 8009DD18 7410801F */ .word 0x1F801074
```

File offset `0x8E514` of `SLUS_007.39` holds `70 10 80 1F`, i.e. `0x1F801070`.
The next slot is `gInterruptMaskPtr` (`0x1F801074`).

## Hardware meaning

The pointer holds the same address as `gInterruptStatusPtr` (`0x1F801070`,
I_STAT), but every unit that uses it declares it as `u16 *`, so the accesses are
halfword reads and writes: the low 16 bits of the interrupt status register.

That distinction matters for acknowledgements. I_STAT clears a source by
writing 0 to its bit; the code here writes `~(1 << i)` through a 16-bit pointer
(`func_800916EC`), which clears one specific interrupt source. Bit numbering
follows public PlayStation documentation.

## Why a second global with the same address

Retail has two separate pointer variables. They happen to hold the same value,
but they are distinct objects at `0x8009DD14` and `0x8009C788`; a rename must
keep them apart so neither declaration's type leaks into the other's units.
Renaming this one to `gInterruptStatusPtr` would also create a duplicate
identifier in units that use both views.

## Correct C type

`volatile u16 *` — pointer to the low halfword of a volatile register.

| unit | declaration |
| --- | --- |
| `func_80091614`, `func_80091A04` | `volatile u16 *` |
| `func_800916EC` | `u16 *` |

## Users

* `func_80091614` — initialisation, publishes the pointer next to
  `gInterruptMaskPtr`.
* `func_800916EC` — reads pending interrupts, masks with `D_8009CCB8 &
  *gInterruptStatusHalfPtr & *gInterruptMaskPtr`, and acknowledges one source
  with `*ptr = ~(1 << i)`.
* `func_80091A04` — pointer bookkeeping during IRQ setup.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
u16 status = *gInterruptStatusHalfPtr;      /* reads I_STAT low halfword */
*gInterruptStatusHalfPtr = ~(1 << i);       /* clears source i           */
u32 addr = (u32)gInterruptStatusHalfPtr;    /* 0x1F801070, no effect     */
```

## C integration status

Renamed from `D_8009DD14` to `gInterruptStatusHalfPtr` in its three C users;
the retail symbol is kept with `__asm__("D_8009DD14")`. No object is defined,
the retail word stays in `asm/us/main.s`, and all three units still compile to
the exact retail bytes (SHA-256 compared before and after the rename).
