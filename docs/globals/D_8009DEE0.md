# D_8009DEE0 — DMA channel 6 channel control pointer

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009DEE0` |
| C name | `gDma6ChannelCtrlPtr` |
| slot address | `0x8009DEE0` (4 bytes, writable, inside the payload's `.text`) |
| initial value | `0x1F8010E8` |
| points at | DMA channel 6 channel control register (CHCR6) |
| assembler label | `DMA6_CHANNEL_CTRL_ASM` in `include/game/dma_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009DEE0
    /* 8E6E0 8009DEE0 E810801F */ .word 0x1F8010E8
```

File offset `0x8E6E0` of `SLUS_007.39` holds `E8 10 80 1F`, i.e. `0x1F8010E8`.

## Hardware meaning

`0x1F8010E8` is `DMA6_CHCR`, the channel control register of the
ordering-table clear channel. The unit stops the channel with `0` and then
writes `0x11000002` to start it, and later polls bit `0x1000000` for
completion. The exact field encoding of `0x11000002` is not proven here; only
the value and the polled bit are measured.

## Correct C type

`u32 *`.

## Users

* `func_8009415C` — clears the channel, starts the transfer and waits for
  completion.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDma6ChannelCtrlPtr = 0x11000002;             /* starts the clear */
while (*gDma6ChannelCtrlPtr & 0x1000000) { }   /* waits for it     */
u32 addr = (u32)gDma6ChannelCtrlPtr;           /* 0x1F8010E8       */
```

## C integration status

Renamed from `D_8009DEE0` to `gDma6ChannelCtrlPtr` in its single user; the
retail symbol is kept with `__asm__("D_8009DEE0")`. No object is defined, the
retail word stays in `asm/us/main.s`, and the unit still compiles to the exact
retail bytes (SHA-256 compared before and after the rename).
