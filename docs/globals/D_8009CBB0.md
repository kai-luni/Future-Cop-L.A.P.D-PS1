## Retail evidence

    /* 8D3B0 8009CBB0 B810801F */ .word 0x1F8010B8

```

File offset `0x8D3B0` of `SLUS_007.39` holds `B8 10 80 1F`, i.e. `0x1F8010B8`.
The zero word behind it is a second, unrelated slot (`D_8009CBB4`), not part of

    /* 803EC 8008FBEC B0CB428C */  lw         $v0, %lo(D_8009CBB0)($v0)
    /* 803F0 8008FBF0 00000000 */  nop
    /* 803F4 8008FBF4 0000428C */  lw         $v0, 0x0($v0)
```

## Hardware meaning

`0x1F8010B8` is `DMA3_CHCR`, the channel control register of DMA channel 3,
the CD-ROM channel:

* bit 24 — start/busy (set to start, reads 1 while the transfer runs)
* bits 28–30 — sync mode
* bit 0 — transfer direction (0 = to RAM, 1 = from RAM)

The game starts a sector transfer with `0x11000000` and `0x11400100` and then
polls bit 24 until the channel reports completion. The nearby pointers
`D_8009CBA8` and `D_8009CBAC` (address and block control of the same channel)
are separate globals and are not renamed here. Bit numbering follows public
PlayStation documentation.

## Correct C type

`volatile u32 *` — pointer to a volatile 32-bit register.

| unit | declaration |
| --- | --- |
| `func_8008FC30`, `func_8008FD30` | `volatile u32 *` |
| `func_8008FAC8` | `int *` |

`func_8008E5B8` mentions the symbol only in its doc comment; it has no
declaration and therefore stays unchanged.

## Users

* `func_8008FAC8` — waits until the reply word's bit 24 clears.
* `func_8008FC30` — writes `0x11000000` and polls bit 24 until the transfer
  finishes.
* `func_8008FD30` — writes `0x11400100`, then reads the register back into
  `status`.

`analysis/refs.json` lists 5 references to the slot in 3 functions, all 4-byte
loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDma3ChannelCtrlPtr = 0x11000000;          /* starts the CD-ROM transfer */
while (*gDma3ChannelCtrlPtr & 0x1000000) {} /* polls the busy bit         */
u32 addr = (u32)gDma3ChannelCtrlPtr;        /* 0x1F8010B8, no effect      */
```

## C integration status

Renamed from `D_8009CBB0` to `gDma3ChannelCtrlPtr` in the three C users that
declare it; the retail symbol is kept with `__asm__("D_8009CBB0")`. No object is
defined, the retail word stays in `asm/us/main.s`, and all four units that
mention the symbol still compile to the exact retail bytes (SHA-256 compared
before and after the rename).
