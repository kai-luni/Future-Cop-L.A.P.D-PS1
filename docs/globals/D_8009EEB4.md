## Hardware meaning

The value `0x1F8010F0` is DPCR, the DMA control register (bits 0–2 priority,
bit 3 enable per channel). It sits next to the SPU base pointer in the SPU
driver's data, and the SPU driver sets `0xB0000` — bits 16–19, the priority and
enable nibble of DMA channel 4 — before transferring voice data.

**Uncertain / naming note:** the C name says "delay control" because the retail
documentation strings and the driver context call this register the delay
register; the value, however, is the DMA control register, so the name
describes the role in the driver, not the hardware identity. Two other retail
pointers hold the same address (`D_8009DD1C`, `D_8009DEE4`) and are named
separately.

## Correct C type

`u32 *` in both users (`func_80096EB8`: `u32 *`, `func_800978E8`:
`unsigned int *`).

## Users

* `func_80096EB8` — sets `0xB0000` (channel 4 priority/enable) during SPU
  initialisation and uploads the 0x10-byte table to SPU RAM `0x200`.
* `func_800978E8` — clears bits 16–18 with `&= 0xFFF8FFFF`.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gSpuDelayCtrlPtr = *gSpuDelayCtrlPtr | 0xB0000;   /* DPCR nibble 4 */
u32 addr = (u32)gSpuDelayCtrlPtr;                  /* 0x1F8010F0    */
```
