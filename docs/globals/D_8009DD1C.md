## Hardware meaning

`0x1F8010F0` is `DPCR`, the DMA control register. It holds four bits per DMA
channel (0–6, plus the OTC channel):

* bits 0–2 of each nibble — channel priority (0 lowest … 7 highest)
* bit 3 of each nibble — channel enable (0 = stopped, 1 = enabled)

The game writes `0x33333333` (priority 3 on every channel, all channels
disabled) and later masks with `0x77777777` (clears bit 3 of every nibble, i.e.
disables all channels). The bit layout follows public PlayStation
documentation; the code only shows the two constants.

## Correct C type

| unit | declaration |
| --- | --- |

## Users

* `func_80091614` — writes `0x33333333` during DMA/IRQ initialisation.
* `func_80091A04` — reads the register into a local, then clears all channel
  enables with `&= 0x77777777`.
* `func_80091AA4` — takes the register address as a destination word for a
  hardware register dump (`func_8008C9B0`), so it does not program the register
  itself.

`analysis/refs.json` lists 4 references to the slot in 3 functions, all 4-byte
loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDmaControlPtr = 0x33333333;   /* programs DPCR                    */
u32 addr = (u32)gDmaControlPtr; /* 0x1F8010F0, no side effect       */
```

Note the cast in `func_80091A04`: `*(u32 *)gDmaControlPtr` re-types the register
but still addresses `0x1F8010F0`, it does not touch the slot at `0x8009DD1C`.

## C integration status

Renamed from `D_8009DD1C` to `gDmaControlPtr` in the three C users; the retail
symbol is kept with `__asm__("D_8009DD1C")`. No object is defined, the retail
word stays in `asm/us/main.s`, and all three units still compile to the exact
retail bytes (SHA-256 compared before and after the rename).
