## Retail evidence

`asm/us/main.s`:

```
dlabel D_8009E9F8
    /* 8F1F8 8009E9F8 F010801F */ .word 0x1F8010F0
```

File offset `0x8F1F8` of `SLUS_007.39` holds `F0 10 80 1F`, i.e. `0x1F8010F0`.

## Hardware meaning

`0x1F8010F0` is `DPCR`. The MDEC unit enables channels 0 and 1 with
`|= 0x88` — bit 3 of nibble 0 and bit 3 of nibble 1, the enable bits of the
MDECout and MDECin channels. Five retail pointers hold this address; the name
records the path, not a separate register.

## Correct C type

`u32 *`.

## Users

* `func_80096240` — enables the two MDEC channels before programming their
  address, block and channel control registers.
* `func_800962D0` — mentions the pointer in its transfer description.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gDmaControlMdecPtr |= 0x88;         /* enables MDEC DMA channels */
u32 addr = (u32)gDmaControlMdecPtr;  /* 0x1F8010F0                */
```
