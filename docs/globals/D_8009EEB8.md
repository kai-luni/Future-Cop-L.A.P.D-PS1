## Hardware meaning

`0x1F801014` is the SPU delay register: it holds the access timing the memory
interface uses for the SPU area. The two units that touch it change single bits
on top of the current value:

* `func_80097940` — `(*p & 0xF0FFFFFF) | 0x20000000` (clears bits 24–27, sets
  bit 29)
* `func_80097968` — `(*p & 0xF0FFFFFF) | 0x22000000` (as above, plus bit 25)

Which timing configuration those bits select is **not** established by the code;
only the bit positions are measured. The register number follows public
PlayStation documentation.

## Correct C type

`u32 *` in both users (non-volatile, as matched).

## Users

* `func_80097940` — sets bit 29 during SPU setup.
* `func_80097968` — sets bits 29 and 25.

`analysis/refs.json` records the slot loads; the slot itself is never written.

## Accessing the variable vs. the register

```c
*gSpuAccessDelayPtr = (*gSpuAccessDelayPtr & 0xF0FFFFFF) | 0x20000000;
u32 addr = (u32)gSpuAccessDelayPtr;   /* 0x1F801014, no side effect */
```
