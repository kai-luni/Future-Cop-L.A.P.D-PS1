# D_8009DEC4 — GPU GP0 port pointer

## Identity

| item | value |
| --- | --- |
| retail symbol | `D_8009DEC4` |
| C name | `gGpuGp0PortPtr` |
| slot address | `0x8009DEC4` (4 bytes, writable, in the payload's `.text`) |
| initial value | `0x1F801810` |
| points at | GP0 command/data port on write, GPUREAD on read |
| assembler label | `GPU_GP0_PORT_ASM` in `include/game/gpu_globals.h` |

## Retail evidence

`asm/us/main.s`:

```
nonmatching D_8009DEC4

dlabel D_8009DEC4
    /* 8E6C4 8009DEC4 1018801F */ .word 0x1F801810
```

The value comes straight from the executable: file offset `0x8E6C4`
(`0x800 + 0x8009DEC4 - 0x80010000`) holds the bytes `10 18 80 1F`, i.e.
`0x1F801810` little-endian. The neighbouring slots point at the matching
registers (`D_8009DEC8` → `0x1F801814`, `D_8009DECC` → `0x1F8010A0`, …), so this
is a pointer block, not a set of unrelated constants.

A load of the slot, `func_800949E8`:

```
    /* 851EC 800949EC 0A80033C */  lui        $v1, %hi(D_8009DEC8)
    /* 851F0 800949F0 C8DE638C */  lw         $v1, %lo(D_8009DEC8)($v1)
    /* 851F8 800949F8 000064AC */  sw         $a0, 0x0($v1)
    /* 851FC 800949FC 0A80023C */  lui        $v0, %hi(D_8009DEC4)
    /* 85200 80094A00 C4DE428C */  lw         $v0, %lo(D_8009DEC4)($v0)
    /* 85208 80094A08 0000428C */  lw         $v0, 0x0($v0)
```

The first pair fetches the pointer; the last load reads the register the pointer
points at.

## Hardware meaning

`0x1F801810` is the GPU's GP0 port. Writes push GP0 commands and their
parameters (the FIFO is not ready until GPUSTAT bit 26 is set); reads return
GPUREAD, the answer to the last GP0 read request. Reading GPUREAD consumes
FIFO state, so a read is not interchangeable with a plain memory read. Command
numbering follows the public PlayStation GP0 documentation; it is not derived
from the game's own code.

## Correct C type

`volatile u32 *` — pointer to a volatile 32-bit register. The pointee must be
volatile because the value changes on the hardware side and a read has a side
effect.

The units keep the declaration types they were matched with, because the
qualification is visible in the object code:

| unit | declaration |
| --- | --- |
| `func_8009446C` | `u32 *volatile` (the pointer itself is volatile) |
| `func_800946A8`, `func_80095350` | `volatile u32 *` |
| `func_80094960` | `unsigned int *` |
| `func_800949E8` | `u32 *` |

Unifying them changed the generated code for several units when measured, so
they are deliberately left alone.

## Users

Writes through the pointer (GP0 commands and pixel data):

* `func_8009446C` — `0x1000000`, `0xA0000000`/`0xB0000000`, two header words,
  then the pixel words of an image transfer.
* `func_800946A8` — `0x1000000`, `0xC0000000`, two words from a packet, then a
  read-back loop into a buffer.
* `func_80094960` — a run of data words after a GP1 command.
* `func_80095350` — a GP0 command built from the low 14 GPUSTAT bits
  (`(*gGpuGp1PortPtr & 0x3FFF) | 0xE1001000`), followed by a dummy read.

Reads through the pointer:

* `func_800949E8` — returns `*gGpuGp0PortPtr & 0xFFFFFF`.
* `func_80095350` — compares the low 24 bits with 2 and performs a dummy read
  when the value differs.
* `func_800946A8` — reads GPUREAD words into the caller's buffer.

`analysis/refs.json` lists 14 references to the slot in 5 functions, all 4-byte
loads (`kind: image`), none of them a store — the slot itself is never written
after startup.

## Accessing the variable vs. the register

```c
u32 port = *gGpuGp0PortPtr;      /* GPUREAD: hardware read, FIFO side effect  */
u32 addr = (u32)gGpuGp0PortPtr;  /* the slot value 0x1F801810, no side effect */
```

## C integration status

Renamed from `D_8009DEC4` to `gGpuGp0PortPtr` in all C users; the assembler
symbol is bound with `__asm__("D_8009DEC4")`. No object is defined, the retail
bytes remain in `asm/us/main.s`, and all 18 affected units still compile to the
exact retail bytes (SHA-256 compared per unit, see `docs/globals/README.md`).
